## 它解决什么问题

一个人对着 AI 干活，最容易出的问题不是「它不会写代码」，而是**它在你没想清楚的地方自己替你决定了**。

这个插件把一次任务拆成一支**有编制的小队**，并且强制一条纪律：

> **需求来自你的原话与已定决定。** 没有静默假设，用户确认共享理解之前不动手。

具体落在四件事上：

| | 做法 |
|---|---|
| **问清楚** | Lead 分轮把问题**一次列完**，用聊天界面的**提问卡片**（选项 + 推荐项）问你。卡片的答案以工具结果回到**同一个回合**，会话不断 |
| **分好工** | 12 个角色按工作流阶段排好，按需叫、不必叫满；每个角色自带使命与纪律 |
| **有交付** | 队员做完必须调 `report_result`（状态 / 证据 / 验收 / 未决项），插件把它投递给 Lead |
| **看得见** | 工作区画布把真实团队拓扑画出来：谁在跑、花了多少 token、谁把文件交给了谁 |

## 快速开始

```bash
# 1. 先完全退出 DSH 桌面端（官方要求 desktop profile 的操作在它退出后进行）
# 2. 在本目录执行
node tools/install.cjs
```

然后重启桌面端 → 新建会话 → 推理模式选「**调度模式**」→ 输入 `/team`。

- 只想看这条命令会做什么、不改任何东西：`node tools/install.cjs --dry-run`
- **界面安装**（等价路径）：插件 → 已安装 → 添加插件 → 填本目录的**绝对路径**，然后再跑一次 `node tools/repair.cjs --apply`

> **为什么装完还要补跑一次 `repair.cjs --apply`**
> 官方安装器不负责两件必需品：包内指向 `~/.dsh/profiles/node_modules` 的依赖 junction
> （缺了插件行在**加载期**就起不来），以及 profile 层的 `agent-team` 容量覆盖
> （缺了有效容量退回官方默认 8，8 次派活之后团队就派不出人）。
> `install.cjs` 会自动串跑它；走界面安装时才需要手动补一次。

> **注意**：安装会把 profile 指向**你运行 `install.cjs` 的那个目录**。
> 如果你另外留着一份副本，那份就是死代码 —— 改它不会生效。
> 用 `node tools/repair.cjs` 可以确认 profile 实际链接到哪一份。

### 装完之后在哪里找

| 入口 | 去哪 |
|---|---|
| **左侧栏「智能体团队」** | 直接进**配置页**（每个角色的模型 / 思考强度 / 预设） |
| **插件 → 已安装 → 调度模式智能体团队** | 同一个配置页的详情视图 |
| **会话顶栏「智能体团队」** | 成员面板；面板里「成员」标题右侧有**进入工作区**（拓扑画布） |
| **推理模式选择器** | 多出「调度模式」 |

> 侧栏那个按钮进的是**配置页**，不是工作区画布；工作区要从**会话顶栏**的成员面板进。
> 两处入口各管各的。

> 本插件**不**改新会话的默认 preset（安全选择：preset 配错会让新建会话直接失败）。
> 要用调度模式请手选一次；已开始过的会话不能切换 preset，需要新建会话。

## 12 个角色

按工作流阶段排列。**按需叫，不必叫满**；角色差异只体现在 Lead 派活的那段提示词里，
队员卡与工具目录是**同一份**（这是缓存能命中的前提）。

| 角色 | 干什么 |
|---|---|
| `researcher` | 把「仓库之外」的事实查清楚：已安装依赖的真实实现、上游源码、官方文档、外部 API 与规范 |
| `scout` | 把**本仓库**的事实查清楚：代码位置、真实行为、依赖关系、配置语义 |
| `frontier-auditor` | 在「问完了」之前审查设计树：找出被静默假设、被跳过、或还没问过就当作已定的分支 |
| `plan-critic` | 动手之前把**已经写出来的计划**打穿：缺口、不可行处、隐藏假设、越界、成本误判 |
| `builder` | 在指定的写域内把改动做出来，并自证可运行 |
| `integrator` | 把多个写域的产出合成一个能真正跑起来的整体，对端到端链路负责 |
| `tester` | 把缺陷变成可重复的失败用例，把修好的行为锁成回归用例 |
| `verify` | 按**验收标准**判定结果：走真实调用链路，覆盖逻辑与边界 |
| `red-team` | 假定交付物是坏的：主动构造能打穿它的输入、时序与环境，目标是**证伪**而不是确认 |
| `visual-critic` | 审查**实际产出**的视觉结果，而不是想象出来的结果 |
| `refiner` | 在不破坏正确性的前提下做根因与简化，把经验固化成可复用的纪律 |
| `scribe` | 把已经定下来的决定与术语写下来，让下一个人不用重新推一遍 |

## 配置队员的模型与思考强度

插件 → 已安装 → 调度模式智能体团队 → 详情页（或左侧栏「智能体团队」）。

页面顶部有一个**统一选择队员模型与思考强度**：选一次就把下面**所有**角色的对应项都改成这一个；
只想给某个角色特殊待遇时，再单独改它那一行。

- 默认每行都是**跟随 Lead**：不配置 = 不加任何覆盖，队员跟着 Lead 当前的选择走。
- 思考强度依附于模型（档位是**每个模型各自广告**的），所以要先把模型统一才能选强度；
  没统一时它会保持可见但禁用，并写明原因与下一步。
- 统一选择时，思考强度会按新模型重算：仍然支持的档位保留，不支持的退回「模型默认」。
- 改完**立即生效**：已经在跑的队员也在下一次请求就用上新路由，不需要重启。
- 唯一的例外是 `spawn_teammate` 的显式参数（`provider`/`model`/`reasoning_effort`）——
  那是「这一次派活」的命令，会钉在该队员身上。思考强度未显式给时，spawn 会**继承
  Lead 当前生效档并钉住**；模型与路由仍逐请求实时跟随。
- 配置文件在 `~/.dsh/dispatch-agent-team.json`。

### 缓存保活（可选，默认按线路自动判断）

Lead 派完活等队员时，它那段对话前缀可能几分钟到几十分钟没被再读，缓存条目过期后，
下一次真实请求要把整段前缀按**全价**重读一次。

保活的做法：在等待期间用**完全相同的前缀**再发一次请求（输出只要 1 个 token），
让缓存条目「被使用一次」，从而续命。

- 三种模式：`auto`（等线路自己证明有缓存命中后才开，**默认**）/ `on` / `off`。
- 只在**Lead 没有在途请求**、且确有队员在跑时才 ping；ping 期间来了真实请求立刻放弃。
- ping 的响应**只排空**：文本与工具调用永不进会话、永不执行。
- 连续 2 次报「零缓存命中」就**停掉这条线路**并记录原因（不烧钱）。
- 安全底线：没有 API key / 没有 llm 服务 / 线路不支持 → 一律静默降级成 `off`，绝不抛错。

## 使用

### 开启与关闭团队

这些入口**只在「调度模式」的会话里**出现（别的 preset 看不到、也开不了本插件的团队）。

| 操作 | 怎么做 |
|---|---|
| 开启 | 输入 `/team`（推荐，`/` 菜单里能搜到），或直接说「组队」「开团队」让 Lead 自己开 |
| 关闭 | 直接说「关掉团队」「解散团队」，Lead 会调 `disable_agent_team` |

- **没有 `/team-off`**：团队开关只有一个斜杠命令 `/team` 与两个模型工具，不需要记第二个命令。
- 命令执行后命令行只显示 `>_ team`，**不会**再追加一段横幅。
- **不要用 `/智能体团队` 这类自造斜杠命令**：命令名在宿主侧只允许 ASCII，
  未注册的 `/xxx` 会被客户端命令面板吞掉 —— 既不报错也不发给模型，也就是什么都不会发生。
- 团队开关**按会话记忆**：`/team` 成功后这个会话会被记下来，宿主重启或重开该会话时自动装回来。
- **`/team` 可以带附件**：贴一张截图再打 `/team 帮我查这个报错`，图片会和那行文字一起进 Lead 的上下文。

### 典型的协作节奏

```
你说需求（可以很模糊）
  ↓
Lead 派 1–3 个 scout / researcher 去查事实
  ↓
Lead 把不依赖这些事实的问题【一次性】列成一轮 ──► 你点选提交
  ↓                                    （答案回到同一回合，会话不断）
frontier-auditor 复核有没有被跳过的分支
  ↓
你确认共享理解 ──► Lead 切写域、建任务、派 builder
  ↓
多个写域 ──► integrator 接线
  ↓
verify 走真实链路验证，高风险改动加 red-team 主动证伪
  ↓
Lead 自己复核关键结论后给你最终答案
```

### Lead 能用的工具

| 工具 | 作用 |
|---|---|
| `spawn_teammate` | 创建一个具名队员（带角色；可选覆盖模型 / 思考强度） |
| `send_message` / `broadcast_message` | 给一个 / 多个队员发消息 |
| `list_agents` / `wait_agent` / `interrupt_agent` | 看成员状态、等变化、打断某个队员 |
| `team_task_create` / `team_task_list` / `team_task_get` / `team_task_update` | 共享任务板（含写域与依赖） |
| `wake_teammate` | 队员被输出上限截断、没交报告时叫它**从断点续写** |
| `enable_agent_team` / `disable_agent_team` | 开启 / 关闭团队（`/team` 的模型侧入口） |

队员看到的是另一份子集：没有 `spawn_teammate` / `interrupt_agent`（只有 Lead 能创建或打断），
多一个 `report_result`（交付报告）与 `ask_lead`（中途向 Lead 提问），也没有目标与子代理工具。

## 工作区（团队拓扑可视化）

会话顶栏点「智能体团队」打开成员面板 → 「进入工作区」。

画布上每个方块是一个真实成员，数据全部来自**你自己的会话日志与团队域服务**，不是演示数字：

- **列 = 真实依赖深度**：Lead 在最左；只读别人产出的在左列；互相读写的成员被收进
  虚线「协作核」容器（点容器或顶栏「展开协作核」摊开看内部关系）。
- **线 = 真实关系**：
  - 蓝虚线 = Lead 正在派活（流光 Lead → 队员）
  - 绿实线 = 该队员已向 Lead 交付（流光 队员 → Lead）
  - 紫线 = 承接关系，即「A 写的文件被 B 读了」（越粗共享文件越多）
- **方块内容**：TODO（完成/进行中/总数）、模型、输出/缓存 token、缓存命中率、运行时长、
  输出速度（TPS）、上下文占用圆环、**档位分段条**（两枚色段 = 该队员的 agent 预设族 +
  呈现档：空心段 = 跟随 Lead；整行悬停看确切说明）。
- **底栏**：全队总 token、整体缓存命中率、平均 TPS、承接关系数。
- **点任意方块**弹出该成员的详情浮窗（指标 + 实时对话 + 提问回答）。
- 顶栏可开关流光 / 弱关系、缩放、适配窗口。`Esc` 退出。

### 浮窗与官方聊天界面等价

不是「另做一套再想办法同步」：

- **实时**：浮窗吃的是官方对话自己在用的那份事件窗口，所以思考、正文、工具调用
  都是**一个 token 一个 token 长出来**的，与你在官方界面看到的同帧；这一步结算后
  由宿主的正式对话行接管（按 callId 与 (turn, step) 去重，不会显示两遍）。
- **回答提问**：弹窗里点「提交回答」调的是**官方那张提问卡自己的** `answer()`，
  与你在聊天界面点提交是同一个方法、同一个对象 —— 阻塞中的那次提问当场拿到答案、
  官方卡片自己关闭。**不是**把答案拼成一条消息插进对话。
- 答案批次的形状照抄官方 `submitDrafts`（没填自定义时 `custom` 键**不出现**）：
  写成 `custom: undefined` 会被网关的 lossless-JSON 校验拒掉，那次提问会当场
  以 isError 结算。而官方 `answer()` 永远 resolve、不回报失败，所以弹窗**另外去查
  这次工具调用的结算结果**，只有确认被接受了才说「已回答」；查出来是死的就如实报错。
- 拿不到这套对象层时（宿主版本不对 / 该会话没有活体对象）自动退回「轮询会话日志」，
  功能不丢，只是不再逐 token 实时，并且会如实说明答案只是投递。

### 任务板浮窗 + DAG 聚焦

悬停底栏的任务分段条，浮窗列出每条任务的状态 / 标题 / 归属与关联报告摘要，
每行尾注 `← 依赖任务`（blockedBy 前驱）。

**点一行** = 聚焦它的完整上下游依赖链（链上主色高亮、链外淡出，标题行给出相关条数）；
再点一次或 `Esc` 取消。

### 加载与空是两种态

打开工作区时，画布（队员卡）、底栏（任务板）、浮窗对话（队员报告流）三处
先显示呼吸骨架占位；数据读到后换成真实内容 —— 确认「什么都没有」时才显示空态文案。

如果**首轮就读取失败**（例如宿主正忙），画布上给的是**红字 + 一个「重试」按钮**，
而不是一屏没有任何出路的错误。不点也会自愈：轮询链会继续自动重试。

### 性能

画布用**自适应刷新**：团队在变化时约 1.2 秒一轮，稳定后退回 5 秒一轮（数据没变不重绘，
流光动画与悬停提示都不会被打断）。

宿主侧对会话日志做了**共享快照**：统计、正文、以及「沿 parentSession 上溯」三条路径
共用同一份解码结果，同一份日志在一个刷新周期内只解压一次。

## ops 工具（可选插件 dsh-ops，原生链接）

[dsh-ops](https://github.com/T-Auto/dsh-ops) 是另一个插件：用 Rust 实现的文件检索、后台任务与批量操作，
比宿主同名工具更快、输出更省 token。**本插件不内嵌它、也不依赖它** —— 两个插件各自安装、各自启用；
检测到它在场时，队员**不需要任何配置**就直接看得到它的工具，并额外收到一段简短的使用指引。

分工要说准（实测，别当成「全都一样」）。**dsh-ops 的呈现方式随版本变过**，两代都要认清：

- **0.3.x（旧）**：`file` 组件的工具注册在全局层，Lead 与每个队员都直接看得到；
  `shell` / `background` / `PTC 增强` 注册在**各 agent 自己的作用域**上，各有一道门。
- **0.5.x**：改成「一条预设一档」的 **mode 行族**（`dsh-ops-mode-*` + `dsh-ops-discovery`），
  并且把 file 工具从「全部常驻」改成 **按需加载**：native 档常驻的只有 `ops_read_files`，
  其余（grep / glob / replace / diff / stat / copy / move / remove / read_pdf / read_docx / read_table …）
  要先经 `ops_discover_tools` 选中才在下一步出现；纯 PTC 档常驻的是 `ops_inspect_local_file` 与 `ops_result`，
  其余在 `run_code` 程序里通过 `ops_load_sdk` 加载。
  **所以新版里「工具清单里没有 `ops_grep`」是设计，不是没装好** —— 这是最容易误判的一条。

| dsh-ops 组件 | 队员拿到什么 |
|---|---|
| file | 常驻：`ops_read_files`（0.5.x）/ 整套 `ops_*` 文件工具（0.3.x）。其余按需：`ops_discover_tools` 选中后于下一步出现 |
| background | `ops_run_background` / `ops_job_output` / `ops_job_list` / `ops_job_kill`（需会话处于完全访问）。**0.3.2 起该组件已被 dsh-ops 整体移除** |
| shell | `ops_bash`（一次性 POSIX 命令）+ 把命令执行器换成随包 PowerShell 7 |
| discovery（0.5.x 新增） | `ops_discover_tools` —— file 工具的按需激活入口，native 档才有 |
| PTC 增强 | `ops_batch` / `ops_result`（+ 0.5.x 的 `ops_load_sdk`）—— **仅纯 PTC 档队员** |

三点如实说明：

1. **`ops_batch`/`ops_result` 要纯 PTC 档才有**：本包**不改 dsh-ops 一行源码**，用已有的配置就能拿到 ——
   把该角色的**预设设为 `ptc`** 并**打开它的「批量调用」开关**。注意方向：2026-10-21 起这个开关的语义是
   「**开 = 钉 ptc 档 / 关 = 钉 native 档**」（宿主已删掉 both 档）。所以「关掉批量」恰恰会把它变成原生档。
2. **没装 dsh-ops 的用户零影响**：不注册任何提示词、不多一个字节，插件页也不会出现 ops 组件。
3. **状态可查**：`~/.dsh/dispatch-agent-team-status.json` 的 `opsIntegration` 字段记录组件的挂载事实、
   当前可见的 `ops_*` 清单，以及一句点名的修法。

想确认这套链接在你机器上真的通了（**不用重启 DSH**）：

```bash
node tools/ops-mount-check.mjs
```

它挂真 dsh-ops 组件与真宿主注册表跑一遍，四段各自独立：A 交付态、B 负对照、
C 后台任务、D shell 通道。判定是三值的（true / false / 跳过）。

### 改动后的生效方式

| 改动 | 生效方式 |
|---|---|
| `lib/*.js`（宿主半） | **重启 DSH** |
| `lib/client.js`（浏览器半） | 刷新页面即可 |
| `presets/*.patch.yml`、`cordis.patch.yml` | 重新加载插件后生效 |

```bash

```

### 分支约定

**日常改动一律在 `dev`，提交后推 `origin/dev`；攒一批再合并进 `main`。**

`main` 是仓库默认分支，也是「已发布」的那一份。为什么必须定期合：GitHub 贡献图
**只统计默认分支可达的提交** —— 实测那 17 个提交只推了 dev 时图上当天是 0，
合并进 main 后同一格变成 17。

合并的做法：

1. `git merge-tree --write-tree origin/main origin/dev` 先干跑，确认零冲突；
2. **用临时 worktree 操作**（`git worktree add <tmp> --detach origin/main`），不要在正在运行的
   插件目录里 checkout —— 那个目录是桌面端实际加载的 junction，切分支会当场改变插件代码；
3. `git merge --no-ff origin/dev`（保留合并提交）；
4. 核对 `git diff --stat HEAD origin/dev` 为空，再 `git push origin HEAD:main`；
5. `git worktree remove <tmp>`，确认插件目录仍在 `dev` 且工作树干净。

## 卸载

```bash
node tools/install.cjs --uninstall          # 推荐：走官方 CLI（先退出桌面端）
```

- 界面卸载：插件 → 已安装 → 调度模式智能体团队 → 卸载。
- 卸载后把推理模式选择器里的默认 preset 换回你原来的那个。
- 界面卸载或应急摘除**不会**自动回收 profile 层那段托管块（`tool-agent-team: disabled` +
  `agent-team` 容量覆盖），需要自己补一次：`node tools/repair.cjs --revert`（幂等）。
- 角色配置与会话记忆文件会留在 `~/.dsh/` 下，可以手动删。
- DSH 起不来时的应急路径：`node tools/emergency-disable.cjs`（把本插件从 bundles 里摘掉）。
